# gwyfbridge — нативный мост между Gamble With Your Friends и Minecraft

Модуль связывает **два живых процесса**: оригинальную игру *Gamble With Your
Friends* (Unity/Mono) и *Minecraft Java Edition* (Fabric-мод). Выигрыш в казино
превращается в блоки в инвентаре Minecraft, а постройка в креативе —
в настоящие 3D-объекты внутри запущенной игры, которые видят все игроки лобби.

```
        ┌─────────────────────────────┐            ┌───────────────────────────┐
        │  Gamble With Your Friends   │            │   Minecraft Java (JVM)    │
        │  (Unity, Mono)              │            │   Fabric-мод              │
        │                             │            │                           │
        │  GWYF_HookEngine.dll        │            │  GwyfBridgeMod (Java)     │
        │   ├─ перехват ставок        │            │   ├─ приём событий        │
        │   ├─ перехват столов        │            │   ├─ выдача блоков        │
        │   └─ VoxelTo3DWorld.cpp     │            │   └─ захват правок блоков  │
        │        (создание кубов)     │            │                           │
        │             ▲               │  общая     │        ▲                  │
        │             │               │  память    │        │                  │
        │      ipc::Bridge ◄──────────┼────────────┼──► gwyf_native_bridge.dll │
        └─────────────────────────────┘            └───────────────────────────┘
                                  ▲
                       gwyfbridge.exe (инжектор, диагностика, самотест)
```

## Состав модуля

| Компонент | Файлы | Что делает |
|---|---|---|
| Движок в игре | `src/GWYF_HookEngine.cpp`, `src/HookEngine.cpp`, `src/MonoRuntime.cpp`, `src/PatternScan.cpp` | DLL, живущая внутри игры: разрешение целей по именам из `Assembly-CSharp`, перехват вызовов (`mono_runtime_invoke` или JIT-адрес метода), публикация событий в общую память |
| Мир в игре | `src/VoxelTo3DWorld.cpp`, `src/VoxelWorld.cpp` | Создание настоящих объектов внутри игры: Unity-примитив, фабрика игры или нативный экспорт; бюджет на кадр, пул объектов, удаление при сломе блока |
| Мост для JVM | `src/Native_JNI_Bridge.cpp`, `src/McWireFormat.cpp` | Нативная библиотека, которую загружает мод: JNI-вызовы вместо пайпов, стабильный формат записей и хеш раскладки |
| Транспорт | `src/IpcProtocol.cpp`, `src/IpcBridge.cpp` | Разделяемая память + события WinAPI: два SPSC-кольца записей и два байтовых кольца, без блокировок и без ожиданий в игровом потоке |
| Конфигурация | `src/TargetProfile.cpp` | `gwyf.profile`: какие классы/методы/поля перехватывать и как раскладывать их значения по полезной нагрузке |
| Инструменты | `tools/cli/GwyfBridgeCli.cpp`, `tools/selftest/selftest.cpp`, `tools/fakehost/fake_mono_host.cpp` | Инжектор/диагностика, самотест, синтетический хост с поддельным Mono |
| Мод | `mod/` | Fabric-мод: приём событий, выдача блоков, отправка правок блоков |

## Сборка

### Windows (Visual Studio)

```powershell
# 1. Нативная часть: настраиваем CMake под VS 2022 и собираем
cd native
# Visual Studio берётся установленная: 17 2022 или 18 2026
cmake -S . -B build -A x64
cmake --build build --config Release

# 2. Самотест (включая интеграционный прогон с синтетическим хостом)
ctest --test-dir build -C Release --output-on-failure
```

Если JDK не установлен, цель `gwyf_native_bridge` пропускается с понятным
предупреждением — остальное собирается. Путь к JDK задаётся так:
`cmake -S . -B build -DJAVA_HOME="C:/Program Files/Java/jdk-21"`.

Visual Studio 2022 умеет открывать папку с `CMakeLists.txt` напрямую
(**File → Open → Folder**), а `native-injection/build_windows.ps1` делает то же из
командной строки.

Готовые артефакты: `build/Release/GWYF_HookEngine.dll`,
`build/Release/gwyf_native_bridge.dll`, `build/Release/gwyfbridge.exe`,
`build/Release/gwyfbridge_selftest.exe`, `build/Release/fake_mono_host.dll`.

### Linux (переносимая часть)

Ядро протокола, зеркало вокселей, разбор профиля и формат для JVM не зависят
от Windows, поэтому их можно собрать и прогнать самотестом где угодно:

```bash
cmake -S native -B build-native -DCMAKE_BUILD_TYPE=Release
cmake --build build-native -j
ctest --test-dir build-native --output-on-failure
```

### Мод Minecraft

```bash
cd native-injection/mod
gradle build          # или ./gradlew build, если добавлен wrapper
```

Мод соберётся без нативной библиотеки, но при запуске сообщит, что мост не
открыт. Положите `gwyf_native_bridge.dll` в `config/gwyfbridge/` (или используйте
задачу `copyNativeLib`, которая кладёт DLL рядом со сборкой, если она найдена).

## Порядок работы

1. **Соберите нативную часть** (см. выше) и мод.
2. **Запустите игру** и узнайте её PID: `gwyfbridge.exe inject --process <имя.exe> --dll <путь>`
   (или `--pid 1234`). Инжектор сам вызовет `GWYF_Init` внутри процесса.
3. **Запустите Minecraft** с модом. Мод откроет мост и напишет в лог строку
   диагностики; если хеш раскладки не совпадёт — обмен отключится с понятной
   ошибкой, а не с «тихо неправильными» блоками.
4. **Проверьте связь**: `gwyfbridge.exe status` — покажет ABI, очереди, пульс.
5. **Сядьте за стол**: выигрыш выдаёт блоки; постройка в креативе появляется
   в игре у всех.

## Поиск целей: почему не офсеты

Игра собрана на Unity/Mono, поэтому вместо жёстко зашитых адресов модуль
разрешает цели **по именам** через метаданные Mono:

```
gwyfbridge.exe dump --class Game.BetManager
gwyfbridge.exe scan --module GameAssembly.dll --pattern "48 8B ?? 05"
```

`dump` вернёт список методов с числом параметров и поля со смещениями — это
готовые данные для `gwyf.profile`. Профиль читается заново командой `reload`
и правится без пересборки: имена в нём — рабочая гипотеза, а не «истина в
последней инстанции», и подтверждаются `dump` на конкретной сборке игры.

### Режимы перехвата (`mode=`)

| Режим | Что перехватывается | Плюсы / минусы |
|---|---|---|
| `invoke` (по умолчанию) | `mono_runtime_invoke` с фильтром по классу и методу | Ничего не патчится в игре, безопасно; видит не все внутренние вызовы (только через runtime) |
| `method` | JIT-адрес конкретного метода (`mono_compile_method`) | Ловит обычные вызовы; требует совпадения раскладки аргументов — она проверяется по сигнатуре |
| `poll` | поле объекта/класса | Вообще без хуков: интервал + публикация при изменении |
| `export` / `rva` / `pattern` | нативная функция | Когда managed-часть не подходит: экспорт, RVA или поиск по сигнатуре |

Раскладок аргументов для `method` немного (12 штук: `void`, `i32`, `i32_i32`,
`i32_i32_i32`, `i64`, `f32`, `f32_f32`, `i32_f32`, `f32_i32`, `i32_i32_f32`,
`obj`, `obj_i32`, `i32_obj`). Перед установкой хука типы сверяются с CIL-сигнатурой
метода: несовпадение = отказ от установки, а не порча стека.

## Профиль `gwyf.profile`

Путь к профилю можно переопределить переменной `GWYF_PROFILE` (иначе берётся
`gwyf.profile` рядом с DLL), имя подставного модуля Mono — переменной
`GWYF_MONO_MODULE`, а имя общего региона — `GWYF_REGION_NAME`: оно имеет
приоритет над `region=` из профиля и нужно, когда рядом работают два экземпляра
(например, автотест не должен мешать запущенной игре).

Рядом с DLL автоматически создаётся шаблон. Основное:

```ini
[bridge]
region=Local\GWYF_MC_BRIDGE_ABI1
log=gwyf_bridge.log
heartbeat_ms=1000
invoke_hook=1

[mono]
assembly=Assembly-CSharp

[watch.bet]
mode=invoke
class=Game.BetManager
method=PlaceBet
params=-1
event=BetPlaced
map=amount:arg0f,chipType:arg0,betKind:arg1     # короткие имена расширяются по секции

[poll.chips]
mode=poll
class=Game.GameManager
field=chips
interval_ms=250
event=ChipState
map=chips:value

[voxel]
mode=unity_primitive
origin=0,0,0
scale=0.5
budget_per_frame=8
pool_limit=4096
despawn_on_break=1

[blocks]
1=dirt
2=grass
3=stone
4=wood
5=gold
6=diamond
7=table
8=lamp
```

Источники значений в `map`: `arg0`…`arg15`, `arg0f` (float), `arg0d` (double),
`this`, `value` (для `poll`), `field(arg0,"имя")`, `static("Класс","поле")`.

## Как создаются объекты в игре (`VoxelTo3DWorld.cpp`)

| Режим | Как создаётся | Когда применять |
|---|---|---|
| `unity_primitive` (по умолчанию) | `GameObject.CreatePrimitive(Cube)` + `Transform.set_position/set_localScale` через Mono | Работает на любой Unity-сборке, ничего не требует от реверса |
| `mono_factory` | Метод самой игры, создающий объект (`factory_class`, `factory_method`, `factory_arg_types`) | Когда нужны «родные» объекты игры с её материалами |
| `native_export` | Нативная функция по имени экспорта | Если в игре есть свой нативный слой; используется самотестом |

Все вызовы Unity API выполняются **только в главном потоке игры** (хук
`WH_GETMESSAGE`). Перед передачей структур проверяется размер `Vector3`
(12 байт) — при несовпадении адаптер отключается, чтобы не портить память.

## ABI общей памяти

* сигнатура региона `GWMC` (`0x434D5747`), версия `1`;
* имена: `Local\GWYF_MC_BRIDGE_ABI1`, события `..._G2M`, `..._M2G`, `..._STOP`;
* запись кольца — 128 байт (две кэш-линии ровно), полезная нагрузка 64 байта;
* кольца: 512 записей + байтовое кольцо 256 КБ в каждую сторону;
* проверка совместимости: магия, версия, размеры заголовка и ёмкостей.

Формат, который видит Java, описан в `McWireFormat.h`: запись 88 байт,
пакет правок 20 байт на элемент. Раскладка имеет **хеш** (`64A0AD23`):
мод считает тот же хеш из нативного текста раскладки и при расхождении
отключает обмен. Хеш считается и по полю `bet.flags` — если флаги ставки
разъедутся между C++ и Java, обмен остановится, а не «поедут» значения.

## Проверка: что реально проверено, а что нет

Самотест (`gwyfbridge_selftest.exe`) прогоняет:

* ABI: размеры структур, упаковка float, отказы при несовпадении версии;
* кольца: порядок, сохранность полей, переполнение, **200 000 записей из двух
  потоков без потерь и дублей**, перенос кадра через границу буфера;
* формат для JVM: упаковка/распаковка (в том числе отрицательные координаты);
* зеркало вокселей: спавн/удаление, бюджет кадра, предел пула, идемпотентность
  повторной установки блока, отказ адаптера;
* профиль: разбор, вычисление источников, запись значений в нагрузку,
  проверка раскладок хуков;
* Windows: MinHook (установка, детур, трамплин, снятие), поиск паттерна по
  собственной памяти, RVA, **двусторонний обмен через разделяемую память
  между двумя концами моста в одном процессе**;
* интеграция (`--integration`): движок внутри синтетического хоста с поддельным
  Mono — разрешение классов/методов/полей, установка хука и публикация события
  `BetPlaced`, которое читает «сторона Minecraft».

Чего в проверке **нет**: живого запуска оригинальной игры. В сборочной среде
нет ни Windows, ни установленного GWYF, поэтому поведение подтверждено на
уровне компиляции и синтетического хоста; окончательная проверка в игре —
на вашей машине. Начинайте с `status` и `spawn-probe` — они дают быстрый ответ,
работает ли цепочка целиком.

## Ограничения и предупреждения

* **Только приватные лобби с друзьями.** Инструмент меняет состояние живой игры
  (создаёт объекты через штатные Unity-вызовы) и выдаёт блоки в Minecraft.
  В публичных лобби это порча чужой игры и нарушение правил — так делать нельзя.
* Никаких обходов защиты: модуль не снимает анти-чит, не скрывается от
  сканеров и не патчит проверки. Если в игре появится защита — считайте, что
  инструмент перестанет работать, а не «обойдёт её».
* Мост не читает и не пишет чужие процессы за пределами общей памяти: единственная
  запись — адрес пути DLL при инжекции и создание объекта в самой игре.
* Выдача блоков — клиентская и только в креативном режиме. На чужом сервере
  серверная логика и анти-чит отбросят такую выдачу — это ожидаемо.
* Игра на IL2CPP: адаптер Mono неприменим (в `IpcProtocol`/`MonoRuntime` есть
  явное сообщение об этом). Понадобится свой слой чтения метаданных.
* Стабильность игры после долгого создания тысяч объектов не гарантируется:
  следите за `pool_limit`, `budget_per_frame` и используйте `flush`.

## Диагностика

| Симптом | Что проверить |
|---|---|
| `Мост недоступен` в CLI | Игра запущена? DLL внедрена (`inject`)? Мод загружен? |
| Мод пишет «раскладка не совпадает» | Собраны разные ревизии: пересоберите DLL и мод вместе |
| `Mono не найден ни под одним из имён` | Игра на IL2CPP или DLL внедрена до загрузки Unity — движок повторит попытку сам |
| События не приходят | `dump --class ...` покажет реальные имена методов: поправьте `class=`/`method=` в профиле |
| Кубы не появляются | Лог рядом с игрой (`gwyf_bridge.log`), строка про адаптер; `spawn-probe` для проверки |
| Инжектор: `OpenProcess не удался` | Запустите от администратора, проверьте разрядность (нужна x64) |

Логи: `gwyf_bridge.log` (игра), `gwyf_bridge_mc.log` (JVM).
