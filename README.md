# Gamble With Your Crafts

[![build](https://github.com/Clayworld20/Gamble-with-your-crafts/actions/workflows/build.yml/badge.svg)](https://github.com/Clayworld20/Gamble-with-your-crafts/actions/workflows/build.yml)

Азартный стол и креативная воксельная стройка в одном исполняемом файле на C# (.NET 8), **без Unity** и **без собственных серверов**: лобби, приглашения и весь игровой трафик идут через Steam P2P (Facepunch.Steamworks).

Сетевая часть работает на **тестовом AppID 480 (Spacewar)** — его Valve держит специально для отладки, публиковать игру в Steam не нужно. Для игры с друзьями достаточно, чтобы у всех был запущен клиент Steam.

```
Стройка из блоков  →  блоки становятся ставками  →  выигрыш приносит новые блоки  →  из них строится дальше
```

---

## Что уже работает

| Механика | Как реализовано |
|---|---|
| Лобби Steam | `CreateLobbyAsync` + видимость `public` / `friends only` / `private`, поиск публичных лобби по тегу |
| Приглашение друзей | официальный оверлей `SteamFriends.OpenGameInviteOverlay` + приглашение конкретного друга + приём `+connect_lobby` |
| Обмен данными | прямые P2P-пакеты `SteamNetworking.SendP2PPacket` / `ReadP2PPacket` (надёжный и быстрый каналы), без сторонних серверов |
| Креатив-инвентарь | `Dictionary<string, int>`: `dirt`, `grass`, `stone`, `wood`, `gold`, `diamond`, `table`, `lamp` |
| Воксельный мир | трёхмерная сетка 48×28×48 по умолчанию, установка/снос/заливка объёмов, RLE-снимок мира для новых игроков |
| Казино | кости 2d6 и европейская рулетка (0..36), ставки — воксельными блоками, выигрыш начисляет хост |
| Рендер | ASCII: срез по высоте (`map`) и изометрия (`iso`) с цветными глифами |
| Одиночный режим | полный запуск без Steam: стройка, инвентарь и казино работают локально |
| Тесты логики | `--selftest`: 199 проверок протокола, сетки, инвентаря, правил казино и сетевой репликации — прогоняются в CI |

## Требования

* **Windows x64** (в поставке Facepunch.Steamworks из NuGet идёт `steam_api64.dll`) — Linux/macOS тоже соберутся, но нужна соответствующая сборка нативной библиотеки.
* **Клиент Steam**, запущенный и залогиненный, с добавленным в библиотеку **Spacewar (AppID 480)** — он бесплатный.
* **.NET 8 SDK** — чтобы собрать; для запуска готовой сборки хватает .NET 8 Runtime.

```bash
git clone https://github.com/Clayworld20/Gamble-with-your-crafts.git
cd Gamble-with-your-crafts
dotnet build -c Release
```

> Если при первом запуске Steam пишет, что AppID недоступен — откройте страницу Spacewar в Steam и добавьте его в библиотеку (кнопка «Играть»). Это официальный тестовый AppID, его используют все разработчики на Steamworks.

## Быстрый старт с друзьями

**Хост** (тот, у кого интернет побыстрее):

```bash
dotnet run --project src/GambleWithYourCrafts -- --host
```

**Друг** — после того как хост пришлёт ID лобби:

```bash
dotnet run --project src/GambleWithYourCrafts -- --join 109775242899999999
```

Ещё два способа позвать друга (команды вводятся прямо в консоли игры):

| Команда | Что делает |
|---|---|
| `invite` | открывает **официальный оверлей Steam** со списком друзей |
| `invite <имя или SteamID>` | приглашает конкретного друга без оверлея |
| `host public` | делает лобби публичным — друг найдёт его командой `browse` |

Если друг принял приглашение, когда игра у него не запущена, Steam сам запустит её с аргументом `+connect_lobby <id>` — приложение это распознаёт и подключается автоматически.

Дальше:

```
craft table                                  # скрафтить стол казино (16 земли + 8 дерева)
place 24 3 24 table                          # поставить стол в мире
bet gold 2 red                               # ставка: 2 золота на красное
bet dirt 10 high dice                        # ставка: 10 земли на «сумма >= 8» в костях
map 3                                        # посмотреть срез мира на высоте 3
iso                                          # изометрический вид постройки
```

## Правила стола

Ставка — **воксельные блоки** из креатив-инвентаря. Ставка списывается сразу; при выигрыше хост начисляет блоки того же типа по коэффициенту. Играть можно только там, где построен стол казино (`table`).

**Кости (2d6)**

| Цель | Условие | Возврат | Шанс | RTP |
|---|---|---|---|---|
| `low` | сумма ≤ 6 | ×2 | 41.7% | 83% |
| `high` | сумма ≥ 8 | ×2 | 41.7% | 83% |
| `seven` | сумма = 7 | ×5 | 16.7% | 83% |
| `double` | дубль | ×6 | 16.7% | 100%\* |
| `snakeeyes` | 1+1 | ×31 | 2.8% | 86% |
| `boxcars` | 6+6 | ×31 | 2.8% | 86% |

**Рулетка (европейская, 0..36, одно зеро)**

| Цель | Возврат | Шанс | RTP |
|---|---|---|---|
| `red` / `black` | ×2 | 48.6% | 97.3% |
| `even` / `odd` | ×2 | 48.6% | 97.3% |
| `low` (1..18) / `high` (19..36) | ×2 | 48.6% | 97.3% |
| `dozen1` / `dozen2` / `dozen3` | ×3 | 32.4% | 97.3% |
| точное число `0..36` | ×36 | 2.7% | 97.3% |

<sub>\* у «дубля» множитель подобран так, что математическое ожидание почти нейтральное — идеальная цель для спора «кто кого переиграет».</sub>

Броски делает **хост** криптографическим ГПСЧ (`RandomNumberGenerator`), результат рассылается всем — подкрутить кубик на своей машине нельзя.

## Архитектура

```
src/GambleWithYourCrafts/
├── AppCore.cs              (1) Инициализация Steamworks на AppID 480, ник игрока, логи, параметры запуска
├── P2PLobbyManager.cs      (2) Лобби, оверлей приглашений, P2P-пакеты, приём/отправка по каналам
├── GambleCreativeSystem.cs (3) Инвентарь + казино + слияние с миром; авторитет хоста, ставки, выплаты
├── VoxelGrid.cs            (4) Данные блоков, сетка, RLE-сжатие, упаковка правок, пресет арены
├── NetProtocol.cs              Типы сообщений, сериализация, фрагментация, абстракция транспорта
├── ConsoleFrontend.cs          Цвета терминала, ASCII-срез, изометрия, разбор команд
├── Program.cs                  Точка входа, игровой цикл, консольные команды
└── SelfTest.cs                 Встроенные тесты логики + loopback-транспорт для тестов сети
```

Первые четыре файла — это структура из задания; остальные четыре — обвязка, без которой не обходится ни одно живое приложение (точка входа, протокол, интерфейс, тесты).

### Как ходят данные

```
Хост (владелец лобби)                     Клиент
────────────────────                      ─────────────────────────
CreateLobbyAsync(maxMembers)
  SetData(game=gwyc, ver=0.1.0+p3)
  SetPublic / SetFriendsOnly / SetPrivate
                                    ←── Hello (ник, версия сборки)
  VoxelSnapshot (фрагменты) ──────────→
  InventorySync (по игроку) ─────────→
  Presence: Joined ──────────────────→
                                    ←── BlockRequest (поставить/сломать)
  проверка границ и ресурсов
  VoxelEdit (всем) ──────────────────→
  InventorySync (автору) ────────────→
                                    ←── CasinoBetRequest (игра, цель, блок, сумма)
  списание ставки, бросок, начисление
  CasinoResult (всем) ───────────────→
  InventorySync (игроку) ────────────→
```

* **Пакет**: `'G' 'C' | версия протокола | тип | тело` — little-endian, строки с varint-длиной. Максимум 4 КБ на пакет, всё большое режется на фрагменты (`Index`/`Count`) и собирается на той стороне.
* **Снимок мира**: сетка 48×28×48 = ~39 КБ сырых данных ужимается RLE в пару килобайт и уходит за 1–2 пакета; новый игрок получает мир сразу при входе.
* **Смена хоста**: владение лобби и роль «авторитета» определяются по `Lobby.Owner`, поэтому если хост вышел, Steam передаёт владение, а новый хост рассылает всем актуальное состояние.
* **Кто чему верит**: авторитетные сообщения (правки мира, выплаты, инвентари) принимаются **только от хоста**; клиент может лишь попросить (`BlockRequest`, `FillRequest`, `CraftRequest`, `CasinoBetRequest`). Клиентский self-report инвентаря принимается один раз — при входе.

### Приватность и «анти-чит»

Это игра для друзей, а не турнир на деньги: полноценной защиты от модифицированного клиента нет и быть не может — хост видит только то, что ему присылают, а любой участник лобби технически может собрать свой клиент с другими правилами. Что сделано по-честному:

* P2P-сессии принимаются **только** от участников текущего лобби (остальные отклоняются и логируются);
* правки мира, результаты раундов и выплаты рассылает исключительно хост — подделка «от клиента» игнорируется (проверяется тестом `TestForgedPacketsRejected`);
* инвентарь не уходит в минус, ставка списывается до броска, отрицательных количеств не бывает.

## Тесты

```bash
dotnet run --project src/GambleWithYourCrafts -- --selftest
```

199 проверок без Steam и без второго компьютера: сериализация всех типов сообщений и отказ от мусора, сборка фрагментов вперемешку, RLE-сжатие, границы мира, инвентарь, коэффициенты и статистика казино (матожидание и равномерность кубика), а также **сетевая репликация** — два игровых сеанса связываются loopback-транспортом и проверяется, что мир и инвентари сходятся после установки блоков, заливки объёма, сноса, ставок, отказа хоста и смены хоста.

CI (`.github/workflows/build.yml`) на каждый push собирает проект (`TreatWarningsAsErrors`, nullable), гоняет эти тесты и публикует одиночный `GambleWithYourCrafts.exe` артефактом.

## Отладка

| Симптом | Причина и решение |
|---|---|
| `Steam не инициализирован: SteamApi_Init returned false` | клиент Steam не запущен / не выполнен вход / Spacewar (480) не добавлен в библиотеку. Игра при этом продолжит работать в одиночном режиме |
| `Unable to load DLL 'steam_api64'` | рядом с `exe` нет нативной библиотеки. Она лежит в NuGet-пакете (`content/steam_api64.dll`) и копируется MSBuild-таргетом при сборке — проверьте, что файл есть в `bin/` |
| Приглашение не открывается | включите оверлей Steam: свойства игры → «Включить оверлей Steam» |
| Оверлей открылся, но друг не получил приглашение | друг офлайн или скрыл статус; отправьте ему ID лобби и пусть выполнит `join <id>` |
| Пакеты не доходят, в логе «Не удалось пробить P2P-соединение» | провайдер режет UDP/NAT — включён `AllowP2PPacketRelay(true)`, трафик пойдёт через релей Steam; при жёстком NAT проверьте, что у обоих открыт порт для Steam |
| «Версия протокола 3 != 4» | у друзей разные сборки: соберите одинаковую версию (метка версии видна в `status` и в списке лобби) |
| Публичный список лобби пуст | лобби с видимостью `friends`/`private` в него не попадают; используйте `host public` |

## Ограничения этой версии

* Мир живёт в памяти: сохранения на диск нет — вышли все, арена обнулится (задел на `VoxelGrid.ToBytes()` для сериализации в файл уже есть).
* Рендер текстовый (ASCII-срез и изометрия) — по заданию нужен был один лёгкий исполняемый файл без Unity.
* Юнитов/физики нет: это песочница-стройка с казино, а не шутер.
* Используется Facepunch.Steamworks **2.3.3 из NuGet** — последняя опубликованная версия. Если брать исходники из `master`, учтите, что там API переписан (`SteamClient.Init` возвращает `void` и бросает исключение, `SteamNetworkingSockets` вместо legacy-P2P) и код потребует правок.
