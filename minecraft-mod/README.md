# Fabric-мод «Gamble With Your Crafts — мост»

Сторона Minecraft для моста с игрой-казино. Мод ничего не патчит в клиенте:
он подписывается на **официальные события Fabric API** и обменивается с игрой
кадрами протокола через файловый канал.

---

## Что делает мод

* **Мир Minecraft → казино.** Игрок сломал или поставил блок — правка уходит в игру
  (`VoxelEdit`), и там появляется «физический» куб, который видят все друзья.
* **Казино → мир Minecraft.** Правки мира казино применяются в Minecraft, а
  результат раунда показывается в чате: кто поставил, на что и чем закончилось.
* **Награды.** На выигрыш приходит `GrantReward` — игрок получает блоки в креативе
  (`giveItemStack`, при полном инвентаре — с выбросом рядом).
* **Снимок региона.** По запросу игры мод отдаёт прямоугольный участок мира одним
  RLE-кадром; обратный снимок из игры применяется к миру.
* **JNI-путь (необязательно).** Если нативная библиотека лежит рядом и загружена,
  правки можно гонять напрямую через JNI, без канала. Обычная игра этим не
  пользуется: Minecraft и казино — разные процессы, поэтому рабочий путь — канал.
  JNI работает только внутри одного процесса, «присоединиться» к чужой JVM нельзя.

Мод честно сообщает о себе: в чат сервера идут строки вида
`[казино] Друг выиграл 24 (×3, цель red)`, а `/gwyc status` показывает состояние
канала, счётчики и задержку.

## Сборка

Нужны **JDK 17** и доступ в интернет (Gradle тянет Minecraft и Fabric из своих
репозиториев).

```bash
cd minecraft-mod
gradle build
# готовый jar: build/libs/gwyc-bridge-1.0.0.jar
```

Версии зафиксированы в `gradle.properties`: Minecraft `1.20.1`, Yarn
`1.20.1+build.10`, Fabric Loader `0.15.11`, Fabric API `0.92.2+1.20.1`.
Тестовый запуск сервера с модом: `gradle runServer`.

## Установка

1. Поставить Fabric Loader под Minecraft 1.20.1.
2. Положить в `.minecraft/mods`:
   * `fabric-api-0.92.2+1.20.1.jar`
   * `gwyc-bridge-1.0.0.jar`
3. Запустить игру и подключиться к своему миру/серверу (мод серверный, но живёт и
   в одиночной игре — там сервер встроенный).
4. Запустить казино с мостом:
   `dotnet run --project ../src/GambleWithYourCrafts -- --bridge <путь к GWYFCraftsBridge.dll>`

## Настройка

Файл `config/gwyc-bridge.properties` создаётся при первом запуске:

| Ключ | По умолчанию | Смысл |
| --- | --- | --- |
| `enabled` | `true` | включён ли мост |
| `channelPath` | `gwyc_bridge.channel` | файл канала; **тот же** должен быть у игры (`--bridge-channel`) |
| `ringCapacity` | `131072` | ёмкость кольца, байт; совпадает с настройкой моста |
| `rewardPlayer` | пусто | кому выдавать награды (пусто — игрок, чьё имя пришло из казино, иначе первый на сервере) |
| `verbose` | `true` | подробный лог в консоль сервера |
| `maxSnapshotSize` | `24` | предел размера региона для снимка по каждой оси |

После правки конфига: `/gwyc reload`.

## Команды

| Команда | Что делает |
| --- | --- |
| `/gwyc` или `/gwyc status` | состояние канала: ёмкость, связь с игрой, счётчики, CRC-ошибки, пересинхронизации |
| `/gwyc reload` | перечитать конфиг и поднять канал, если он был закрыт |
| `/gwyc snapshot` | отправить игре снимок региона вокруг игрока |

Требуются права оператора (уровень 2).

## Как читаются правки блоков

* **Снос** — событие `PlayerBlockBreakEvents.AFTER`: точное и однозначное.
* **Установка** — `UseBlockCallback` плюс проверка на следующем тике: мод
  запоминает состояние места клика и соседней клетки, а через тик сравнивает их и
  отправляет изменившиеся позиции. Так мод не зависит от внутренних методов игры
  и не может её сломать: используются только публичные события Fabric API.

Если в будущем понадобится ловить вообще все изменения мира (например, от поршней
или других модов), это делается миксином на `ServerWorld#setBlockState` — тогда
понадобится отдельный `mixins.json`. Для сценария «друзья строят в креативе»
текущего механизма достаточно, и он безопаснее: мод не вмешивается в код игры.
