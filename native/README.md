# Нативный мост: казино ↔ Minecraft

Мост связывает мир игры **Gamble With Your Crafts** (казино и воксельная стройка)
с миром **Minecraft Java Edition**: блок, поставленный в креативе, появляется
«физическим» кубом в мире казино, а выигрыш на столе казино выдаётся блоками в
Minecraft. Всё в реальном времени, в обе стороны.

---

## Что здесь есть

| Файл | Роль |
| --- | --- |
| `src/GWYF_HookEngine.cpp` | движок перехвата: реестр хуков (MinHook), AOB-сканер сигнатур, счётчики вызовов, наблюдатели событий казино |
| `src/Native_JNI_Bridge.cpp` | каналы связи: разделяемая память (файловый маппинг), именованные пайпы, JNI-путь для JVM в том же процессе; запуск процесса Minecraft |
| `src/VoxelTo3DWorld.cpp` | синхронизация вокселей: схлопывание правок, лимит кубов, RLE-кодек (общий формат с C# и Java) |
| `src/BridgeDll.cpp` | сам плагин: экспорт C-ABI, рабочий поток канала, диспетчер событий на главном потоке игры |
| `include/gwyc/plugin_abi.h` | **контракт плагина**: то, что игра видит и вызывает |
| `include/gwyc/protocol.h` | формат кадра, размеры сообщений, CRC32, типы блоков |
| `include/gwyc/SharedChannel.h`, `RingBuffer.h` | кольцевой буфер SPSC без блокировок и файловый канал |
| `tests/core_tests.cpp` | 113 проверок: протокол, гонки, RLE, воксели, сканер, хуки, сквозной C-ABI |
| `third_party/minhook/` | MinHook (MIT), вендорен целиком: только исходники, без предсобранных бинарников |

## Границы применимости (важно)

Движок умеет перехватывать вызовы **внутри своего процесса**: своя игра, свой
сервер, свой агент — это законный инструмент профилирования и отладки. Читать
память и ставить хуки в **чужую коммерческую игру** («Gamble with Your Friends» и
подобные) нельзя: это нарушает EULA/Steam Subscriber Agreement, ломает чужие
финансовые механики и заканчивается блокировкой аккаунта. Поэтому здесь сделано
иначе и, главное, надёжнее:

* **Игра сама отдаёт события.** Мы владеем кодом своего казино, поэтому ему не
  нужен чужой хук: он экспортирует плагинный ABI (`plugin_abi.h`), а DLL моста
  грузится как обычный плагин. Раскладку структур знает владелец процесса — она
  не «угадывается» по смещениям в чужом бинарнике.
* **Minecraft — через официальный API.** Мод на Fabric подписывается на события
  мира и играет по правилам загрузчика, а не патчит клиент.
* **Хуки остаются инструментом.** `GWYF_HookEngine` применим к *своему* коду:
  адреса функций игра передаёт сама (экспорт или AOB-сканер), а вызовы
  трассируются, не меняя поведение игры.

## Архитектура

```
┌──────────────────────────┐        файловый канал (mmap)        ┌────────────────────┐
│  GambleWithYourCrafts    │  ┌──────────────────────────────┐   │  Minecraft Java    │
│  (C#, .NET 8)            │  │ FileHeader                   │   │  Fabric-мод        │
│                          │  │ ring A: игра → Minecraft     │   │  (BridgeChannel)   │
│  BridgePluginLoader ─────┼──┤ ring B: Minecraft → игра     │───┼─ Payloads / BlockMap│
│  (NativeLibrary + ABI)   │  └──────────────────────────────┘   │  GwycBridgeMod     │
└───────────┬──────────────┘                                      └────────────────────┘
            │ C-ABI (plugin_abi.h)
┌───────────▼──────────────────────────────────────────────────────────────┐
│  GWYFCraftsBridge.dll                                                     │
│  ├── BridgeDll.cpp        экспорт, рабочий поток канала, диспетчер        │
│  ├── SharedChannel.h      SPSC-кольца, кадры с CRC32                      │
│  ├── GWYF_HookEngine.cpp  MinHook + AOB-сканер (для своего кода)          │
│  ├── VoxelTo3DWorld.cpp   схлопывание правок, RLE, лимит кубов            │
│  └── Native_JNI_Bridge.cpp shared memory / named pipe / JNI               │
└───────────────────────────────────────────────────────────────────────────┘
```

* **Формат канала.** `[магия 'GW' | версия раскладки | тип | флаги | размер | CRC32]`
  + payload. CRC32 считается по `тип+флаги+размер` и payload; битый кадр
  отбрасывается, поток при мусоре пересинхронизируется по одному байту.
* **Кольца.** Два односторонних SPSC-кольца: каждый участник пишет только в своё,
  читает только из чужого. Никаких блокировок и мьютексов — игровой поток нельзя
  останавливать на ввод-вывод. Видимость обеспечивают acquire/release-доступы
  (`std::atomic` в C++, `VarHandle` в Java) — это проверено ThreadSanitizer'ом.
* **Потоки.** Весь ввод-вывод живёт в рабочем потоке DLL. Колбэки игры всегда
  поднимаются на её главном потоке из `GwycBridge_Tick()`: игровые системы
  однопоточные.
* **Схлопывание правок.** Пока игрок ведёт мышью линию блоков, в игру уходит не
  500 вызовов на кадр, а итоговый набор изменённых клеток. Последняя правка
  клетки побеждает, есть предел числа кубов (`maxCubes`).

## Сборка

### Windows, Visual Studio (проще всего)

1. Открыть `native/GwycBridge.sln` (VS 2022, набор инструментов v143).
2. Выбрать конфигурацию **Release / x64**.
3. Собрать: `GWYFCraftsBridge.dll` появится в `native/bin/x64/Release/`.
   Тесты — проект `GwycCoreTests` (запускаются как обычное консольное приложение).

### Windows / Linux, CMake

```bash
cmake -S native -B native/build -DCMAKE_BUILD_TYPE=Release
cmake --build native/build --parallel
ctest --test-dir native/build --output-on-failure      # 113 проверок
```

Ключи: `-DGWYC_BUILD_TESTS=OFF` (без тестов), `-DGWYC_WERROR=ON` (предупреждения =
ошибки), `-DGWYC_WITH_JNI=ON` (прямой JNI-путь, нужны заголовки JVM).

Готовые артефакты: `native/build/bin/GWYFCraftsBridge.dll` (или
`libGWYFCraftsBridge.so`) и `native/build/bin/gwyc_core_tests`.

### Что проверяют тесты

`./gwyc_core_tests` печатает 113 проверок по разделам: CRC32 (эталонный вектор),
кольцо SPSC под нагрузкой в 200 000 сообщений, кадрирование (битый CRC, мусор,
пересинхронизация), RLE, схлопывание вокселей и лимит кубов, сканер сигнатур
(поиск реальной функции в своём `.text`), реестр хуков и, наконец, сквозной прогон
**настоящего C-ABI моста**, где вторую сторону канала играет процесс-«Minecraft».

## Как этим пользоваться

### 1. Запустить игру с мостом

```bash
# из корня репозитория, после сборки нативной части
dotnet run --project src/GambleWithYourCrafts -- \
    --bridge native/build/bin/GWYFCraftsBridge.dll \
    --bridge-channel gwyc_bridge.channel
```

Ключи:

| Ключ | Смысл |
| --- | --- |
| `--bridge <файл>` | подключить нативный мост (без него игра работает как раньше) |
| `--bridge-channel <файл>` | файл канала; должен совпадать с настройкой мода |

Что происходит после подключения:

* **казино → Minecraft**: каждая правка мира казино уходит в мод (`VoxelEdit`),
  результат раунда — в чат Minecraft (`BetResolved`), выигрыш автоматически
  превращается в `GrantReward`, и мод выдаёт блоки игроку;
* **Minecraft → казино**: блок, поставленный или сломанный игроком в креативе,
  попадает в мир казино как куб (`VoxelApply`), поэтому друзья видят изменение
  сразу;
* **снимок региона**: игра может запросить у мода прямоугольник мира и применить
  его целиком одним RLE-кадром (`GwycBridge_RequestRegionSnapshot`).

### 2. Проверить, что канал жив

В игре: команда `status` (показывает состояние моста и счётчики), в Minecraft:
`/gwyc status`. В логе игры видно старт моста, задержку до мода (`rttMs`) и
количество потерянных кадров.

## Хуки на события казино

Движок перехвата ставится на функции *своей* игры. Игра передаёт адреса сама:

```c
/* 1. Адрес функции берём у себя: экспорт или AOB-сканер. */
void* betSubmit = gwyc::hooks::FindPatternInModule("GambleWithYourCrafts.exe", "48 89 5C 24 ?? 57 48 83 EC 20");

/* 2. Ставим хуки через ABI моста. */
GwycBridge_InstallCasinoHooks(betSubmit, tableCreate);

/* 3. Смотрим, что перехватили. */
uint64_t bets = 0, tables = 0;
GwycBridge_GetHookCounters(&bets, &tables);
```

Наблюдатели (`SetBetObserver` / `SetTableObserver`) получают контекст и **всегда**
пропускают вызов в оригинал: хук работает как трейсер и не меняет поведение игры.
Вне Windows движок уходит в теневой режим (перехвата нет, реестр и логика
работают) — именно поэтому тесты ядра можно гонять в Linux-CI.

## Диагностика

| Симптом | Причина и что делать |
| --- | --- |
| `мост не найден` | неверный путь в `--bridge`; проверьте, что DLL собрана под ту же разрядность, что и игра |
| `ABI 3, игра ждёт 4` | DLL и exe из разных сборок: пересоберите обе части |
| `не удалось открыть канал` | путь занят другим файлом или нет прав; удалите старый файл канала |
| `раскладка не совпадает` | мод и DLL собраны под разные версии `LAYOUT_VERSION` |
| кадры не идут | мод не на связи: проверьте `/gwyc status` и путь в `config/gwyc-bridge.properties` |
| `overruns` растёт | вторая сторона не читает канал: игра не тикает или мод запущен на другом сервере |
